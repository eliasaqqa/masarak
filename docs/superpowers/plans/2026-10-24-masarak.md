# Masarak Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Deliver a working mobile-first Masarak comparison and cart prototype matching the approved screenshots and scope.

**Architecture:** Flask/Jinja renders pages backed by reusable Python data, comparison, assistant, cart, and checkout services. JSON feeds both presentation and APIs; custom CSS and vanilla JavaScript provide browser interactions.

**Tech Stack:** Python 3.12, Flask, HTML5, CSS3, vanilla JavaScript, unittest; browser automation for functional validation when available.

**Spec:** `docs/superpowers/specs/2026-10-24-masarak-design.md`

## Global Constraints

- Only HungerStation and Ninja for Food and Market.
- Sample prices remain clearly labeled until scraper code arrives; do not scrape external services.
- No frontend framework or Bootstrap; preserve screenshot identity and 320px–desktop responsiveness.
- Rides and hotels are demo/coming-soon experiences.
- Assistant prepares carts; checkout and wallet cannot charge or submit real orders.
- Use the existing isolated checkout; do not create a worktree.
- Use the supplied logo if accessible; report a missing asset rather than redrawing it.

## Review Focus

- Malformed, unavailable, nonfinite, or duplicate prices cannot create false best-price offers.
- Cart requests cannot set prices or use unsupported providers or excessive quantities.
- Missing JSON files produce an explanatory state and an API error rather than a traceback.
- Unknown feature routes return branded 404 pages; unsafe chat text is rendered as text.
- Narrow screens, long content, and fixed navigation do not hide controls or create page overflow.
